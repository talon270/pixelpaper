pixelpaper

A wallpaper for Quickshell on Hyprland. It draws 1-bit desktop scenes (lists, keypads, dialogs) from your live system, drifts them slowly, and stops when other programs need the CPU.

This page runs the real scene generator from the repo. The text is sample data, and scenes change every 20 s here. On a desktop they change about every 4 minutes.

Install

You need Quickshell, Hyprland and a kernel with PSI (Linux 4.20 or later; check that /proc/pressure/cpu exists). Tested with Quickshell 0.3.1 on CachyOS. Other compositors are untested.

  1. Unpack the engine into your Quickshell config folder and start it: 
    mkdir -p ~/.config/quickshell
curl -L https://github.com/talon270/pixelpaper/releases/latest/download/pixelpaper.tar.gz \
  | tar -xz -C ~/.config/quickshell
qs -c pixelpaper -d
  2. Stop your old wallpaper daemon (hyprpaper, swww, swaybg). It draws on the same background layer.
  3. Start pixelpaper with Hyprland. Add this to hyprland.conf: 
    exec-once = qs -c pixelpaper -d
  4. Optional keys for the next scene and the next colour: 
    bind = SUPER ALT, S, exec, qs -c pixelpaper ipc call scene next
bind = SUPER ALT, W, exec, qs -c pixelpaper ipc call palette next

Commands

Every command is qs -c pixelpaper ipc call <target> <function> [argument]. Palette and appearance survive a restart.

TargetFunctionWhat it does
scenenextBuild a new scene now, with fresh live text
scenekind <name>Build one kind: list specimen icons keypad controls field dialog
scenesnap <path.png>Save the first screen's wallpaper as a PNG
palettenext, prevStep through 9 colours, then spectrum (hue turns once an hour) and random (new colour each scene)
paletteset <name|#rrggbb>Pick a palette by name, or any hex colour
palettelist, getPrint the names, or the current one
appearanceset <dark|light|auto>auto follows the caelestia shell's scheme file if you use it

Why it stays cheap

It stops when other programs wait for the CPU.

It reads /proc/pressure/cpu: the share of the last 10 s in which a ready task waited for a core. Above 25% the drift springs to a stop; below 10% it starts again. An idle machine reads about 3%. A job that fills one core while others sit free makes nothing wait, so the wallpaper keeps moving. In testing, a full load stopped it within about 5 s.

Each scene is painted once, then moved.

A new scene costs about 0.8 s of CPU to paint, once every ~4 minutes. Drift moves the painted canvas as one item, so a frame is a transform, not a repaint. On one screen at 20 fps, CPU use fell from 10.2% to 3.1% of one core, and to 0.2% while paused.

It stops when no one can see it.

A fullscreen window on that monitor, or 5 minutes without input, pauses the drift and the scene timer. Video players that inhibit idle keep it drifting under a windowed video. These two pauses are wired up but not yet measured.

It wanders instead of scrolling.

The camera follows two slow sines per axis, so it curves through every direction and stays within 12% of the screen height of the centre. Speed is a critically damped spring: a stop eases out over about 2 s.

Colour changes never repaint.

Ink is black at 20% opacity (17% in light mode) over the base colour, so palette, spectrum and light/dark changes only move the base.

The text is from your machine.

Scenes print your hostname, the playing song (MPRIS), uptime, memory use, battery and workspace names. Values are read when a scene is built and stay until the next one.
